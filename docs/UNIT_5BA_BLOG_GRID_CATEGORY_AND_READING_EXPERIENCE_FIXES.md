# Unit 5BA — Blog Grid, Category Directory, and Reading Experience Fixes

## 1. Title

Unit 5BA — Fix Blog Grids, Build Category Directory, and Improve Article Readability.

## 2. Status

Implemented as a bounded HTML, shared CSS, shared JavaScript, static-generation, verification, and documentation unit. Nothing was deployed, committed, or pushed.

## 3. Purpose

Remove the listing defect reported by the Project Owner, replace the duplicate Categories archive with a registry-driven category directory, and improve the shared reading surface without rewriting article content or changing publication state.

## 4. Project Owner feedback

The Project Owner reported a visible `+`, an apparently empty position in the three-column article grid, a Categories page that duplicated the archive instead of organizing it, and article pages that needed a coordinated black, charcoal, grey, and off-white reading system.

## 5. Root cause of stray `+`

The source was literal stray HTML text immediately before an article card in both `blog/index.html` and the previous generated `blog/category/index.html`. It was not produced by CSS, a pseudo-element, JavaScript, or a debugging overlay. The exact text was a leading `+` before `<article class="blog-article-card">`.

## 6. Root cause of blank grid position

CSS Grid treated the non-whitespace `+` text node as an anonymous grid item. That anonymous item occupied a cell, so the following article card moved to the next cell and made the listing appear to contain a missing or blank card position. No article-card span, empty card wrapper, or intentional spacer caused the defect.

## 7. Grid corrections

- Removed the literal `+` at its source on Insights.
- Replaced the former Categories archive markup, removing its duplicate copy of the defect.
- Retained the existing article-card markup and cover assets.
- Made row flow and stretch behavior explicit on `.blog-card-grid` without adding offsets, placeholders, negative margins, or phantom elements.
- Verified 61 direct article-card children on Insights and no non-whitespace text items in the grid.

## 8. Insights-page impact

The light Knowledge Library, all 61 published cards, unique covers, titles, excerpts, dates, reading times, links, hero, and weekly featured area remain intact. The only Insights markup correction is removal of the stray leading `+`. The filter status now accurately describes the visible records as published articles rather than drafts.

## 9. Categories-page previous behavior

The previous Categories page rendered another complete 61-card archive. It did not provide a category-first directory experience, and it repeated the same stray `+` defect found on Insights.

## 10. New category-directory architecture

The rebuilt default page contains one directory card for each active published category and no article archive cards. Each card includes its name, published count, registry description, up to three representative titles, and a category link. A separate results region is populated only when a category is selected or supplied in the URL.

The directory is generated by `scripts/build-category-directory.mjs`. The focused regression suite in `scripts/test-blog-directory.mjs` verifies directory coverage, uniqueness, counts, default archive exclusion, and published-only links.

## 11. Category-count derivation

Counts are derived at build time from `blog/data/posts.json` records whose status is `published` and whose public URL is valid. Description and ordering metadata come from the existing category registry; stored category counts are not trusted as the source of truth.

## 12. Category navigation behavior

Every directory card has a deterministic URL in the form `category/index.html?category=<slug>#category-results`. Shared `blog.js` reads that query, selects the matching directory item, fetches the local published registry, and renders only that category's published cards. Selection updates `aria-current`; browser back/forward restores the query state; and the clear action returns to the safe directory-only default. Invalid or missing category slugs do not expose an unfiltered archive.

## 13. Article reading-surface changes

The existing dark DaDaStore shell is preserved. Shared CSS now gives `.blog-article-body` a slightly lighter `#171b23` charcoal surface, a softened border, responsive padding, and a restrained shadow. Callouts and blockquotes use slightly lighter charcoal panels, while preformatted examples use a darker contained panel. No article HTML or body copy was edited.

## 14. Typography and contrast changes

- Body text uses warm/cool off-white `#d5d9e2` on charcoal with a maximum readable line length of 68 characters and a 1.82 line-height.
- Lead text and headings use brighter off-white while retaining balanced, bounded heading widths.
- Paragraph and heading separation was increased through shared spacing.
- Links retain cyan, visible underlines, and white/magenta hover and focus treatment.
- Lists inherit the improved body color, line length, and rhythm.
- Blockquotes, callouts, inline notes, code, and preformatted blocks receive distinct, high-contrast treatments without pure-white-on-black glare.
